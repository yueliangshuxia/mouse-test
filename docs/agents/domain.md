# 领域文档

工程技能在探索代码库时,应按以下规则消费本仓库的领域文档。

## 探索之前先读这些

- 仓库根目录的 **`CONTEXT.md`**,或
- 仓库根目录的 **`CONTEXT-MAP.md`**(若存在)—— 它指向每个上下文各自的 `CONTEXT.md`。读取与当前主题相关的那些。
- **`docs/adr/`** —— 读取涉及你即将动工区域的 ADR。

本仓库为**单上下文**布局:根目录一个 `CONTEXT.md` + 一个 `docs/adr/`。

若上述文件不存在,**静默跳过**。不要指出其缺失,也不要主动提议创建。`/domain-modeling`
技能会在术语或决策真正被确定时惰性创建它们。

## 使用词汇表里的词

当你的输出要命名一个领域概念(issue 标题、重构提案、假设、测试名)时,使用 `CONTEXT.md` 中
定义的词。不要漂移到词汇表明确避免的同义词。

如果你需要的概念还不在词汇表里,这是一个信号——要么你在发明项目没有使用的语言(重新考虑),
要么存在真实缺口(记下来交给 `/domain-modeling`)。

## 标记 ADR 冲突

如果你的输出与既有 ADR 相矛盾,明确暴露出来,而不是静默覆盖:

> _与 ADR-0007(事件溯源订单)相矛盾 —— 但值得重开讨论,因为……_
